## 日常使用

1. 在“配置”中维护人员、航班模板、每周航班计划、岗位和规则，或导入配置模板。
2. 在“航班”中确认当天航班、时间、运力和岗位；也可以使用在线查询生成增删建议。在线查询不可用时不影响本地排班。
3. 选择工作日期并生成排班，在真实任务进度完成后查看班表、右侧提前下班与下午无航班名单、人员负荷和规则反馈。
4. 按需要拖拽换人、交换岗位、填写临时岗位或调整当日轮值。
5. 在“统计”中核对月度值班、CX航前、备勤和岗位承担次数，在“历史”中复核已归档班表。
6. 导出 Excel、离线 HTML 或 PNG；确认当天结果后可以仅归档，或点击“归档并排后天”，确认目标星期预设的航班后再归档和生成。

先在“配置 → 每周航班计划”中为星期一至星期日分别勾选已有航班模板。“归档并排后天”会根据目标日期所属星期默认勾选对应预设，并提供“恢复星期预设”“全选”“清空”；弹窗里的临时增减和每个航班手动填写的预定人数只影响本次生成，不会改写每周计划。预定人数达到岗位配置的启用旅客人数时，该岗位才会自动安排。取消、停止、失败或没有完整安全方案时，原日期、航班、历史和班表均保持不变。这个流程只使用本机模板，不要求网络或在线查询。

不参加备勤的人员，可以在“配置 → 人员信息”中关闭“备勤资质”。关闭后，自动轮值、手工选择和值班备勤 Excel 导入都不会再把该人员安排为备勤；若合格人员不足，备勤席位会留空并提示。

每次点击“生成排班”或“重新排班”，系统只计算当前选中的日期，不会提前计算未来两三个班。当天需要自动安排的岗位和所有合格人员会放在一起考虑；最多计算 150 秒，求出完整结果后会立即结束。超过 150 秒或计算失败时不会采用半成品，原班表会继续保留；确实缺少合格人员的岗位可以留空，并显示原因。计算期间可以点“停止，不采用”立即结束并保留原班表；后台准备好一份完整且通过安全检查的方案后，“停止并采用”会启用，可结束后续公平优化并采用最近的安全方案。跨工作日恢复目标可选择“优先避开”或“严格限制”；严格限制下若没有安全完整方案，则本次排班失败并保留原班表。
排班失败时右下角的红色错误提示会一直保留，直到点击提示右侧的关闭按钮；成功和普通提醒仍会按原定时间自动消失。

次班截止时间是上一班末班重点人员在下一班最晚允许继续工作的界线，不要求恰好在该时刻下班。存在多个完整安全方案时，系统按截止更早、上一班结束更晚、最终工作结束更早的顺序，优先把更早下班机会给受保护人员。

人员配置中勾选“分队长”后，该人员仍可正常承担有资质的岗位，但系统不要求他每天必须出现在班表中，也不会为了凑齐“人人有工时”而专门安排岗位。存在安全替代人员时，连续承担 `KE166` 独立督导的分队长可以整班休息；只有分队长是唯一合格人员或更高优先级规则确实需要时才继续安排。

规则页的“普通岗位最小衔接间隔”默认是 90 分钟。同一个人做完一个航班后，到下一个航班开始必须至少留够这段时间；刚好 90 分钟可以，89 分钟不可以。唯一跨航班例外是有效分流：来源岗位已设为“分流”、来源航班在 12:00 及以后开始，并且与下一航班的重叠大于 0 且不超过“提前撤岗分钟”时，可以提前撤岗后直接接续，不再额外等待 90 分钟。早班、没有实际重叠、重叠超限或普通岗位仍严格执行 90 分钟；人员状态、资质、夜班能力、其他时间冲突和每日工时上限不会放宽。这个规则对自动排班、补缺、轮岗、换位和人工拖拽使用同一判断；不需要常规衔接限制时可以手动改为 0。

规则页还可以按顺序添加“跨工作日资质预留”。例如下一工作班某航班的控制岗位至少要留 1 名合格人员，系统会尽量避免今天把所有控制资质人员都排到过晚的岗位，但被保留的人今天仍可做较早、较轻的工作。它不会提前生成下一班，也不会为了预留故意空掉今天本来能填的岗位；两边实在无法兼顾时，今天岗位照常填满，并明确提示下一班还差几名可用人员。

规则页顶部搜索框可以搜索规则名称、说明、参数名称和当前配置内容。例如输入航班号、岗位关键词或 `90`，对应的规则卡会自动展开，无关规则会暂时隐藏；清空搜索后恢复全部规则。

规则页可设置“末班结束界线”，默认是 `23:00`，并勾选哪些航班参加末班重点岗位轮换。系统先守住分类差值，再避开上一工作班已经承担过任意末班重点岗位的人，然后依次比较本月四类合计、最近 8 个归档工作班合计，最后才分别平衡督导、一号、申报和送资料。督导和一号的正常差值为 1，申报和送资料允许差值 2；范围内不报警、不强制追平，督导资质人员也可以因承担督导而少做申报和送资料。

督导、一号、申报、控制和送资料都按航班与岗位滚动轮换：所有合格人员轮完当前次数后，才开始下一轮。重点岗位次数优先于恢复、疲劳、普通岗位衔接和上一班轻重；但不会突破资质、人员状态、夜班、时间冲突、每日工时、值班或 `KE166` 锁定、岗位完整性和严格岗位衔接。

`TR121 / H02` 按“一号”计算，自动排班时每名合格人员每个自然月最多承担 2 次；全部合格人员都达到 2 次后，该岗位自动留空。这个上限只限制自动排班，排班员仍可人工拖拽超过 2 次。值班人员若安排到首选晚撤岗位会使一号次数差超过 1，系统会继续尝试下一个晚撤目标。

统计页提供统一的“末班重点岗位统计”，默认汇总规则页已勾选航班的月度次数。主表先显示每个人的四类合计、督导、一号、申报和送资料总数；点击次数可以展开具体日期、航班和岗位。取消勾选只会让该航班暂时退出后续规则和当前统计，不会删除历史，重新勾选后会立即恢复。

班表生成后，可以在排班工具栏点击“对比上一班”，直接在当前页面上方展开当前排班日期之前最近一个已归档工作日的只读班表。当前班表继续保留在下方；没有更早归档时按钮显示“暂无上一班记录”。对照内容使用现有历史归档数据，不会修改班表或重新计算排班。

岗位旁出现琥珀色提醒时，点击图标即可打开“调整原因分析”。选择想交换的人员后，页面会先模拟两人岗位交换，列出能改善的情况、需要接受的取舍和不能调整的原因；只有结果允许时才能确认交换，确认前系统还会按最新班表再检查一次。

排班计算期间可以继续查看页面和缩放班表，也可以使用两种停止操作；再次计算、切换行政支援、修改数据、导入或归档会提示等待当前任务完成，防止两个操作同时改动班表。当前任务无论成功、失败或停止都会释放后台计算资源，之后可以直接重试。

## 页面入口

| 页面 | 用途                                                         |
| ---- | ------------------------------------------------------------ |
| 总览 | 查看当前日期、航班、人员和排班状态                           |
| 配置 | 维护人员、航班模板、每周计划、岗位和通用参数，导入或导出配置 |
| 航班 | 管理当天航班并进行线上计划对账                               |
| 排班 | 生成、复核、人工调整和导出当天班表                           |
| 规则 | 用中文查看、启停和调整允许配置的排班规则                     |
| 统计 | 管理月度轮值并核对人员与岗位统计                             |
| 历史 | 查看、导入、删除和清空已归档排班                             |

班表根据当前航班和岗位自动生成。航班增加到 5、6、7、8 个或更多时会继续扩展，超过可读宽度后仅班表区域横向滚动；当日轮值在桌面端固定显示于班表右侧，窄屏时自动移到班表上方。

业务数据默认保存在当前浏览器本地；每周航班计划包含在“导出配置”Excel 中，换设备后可通过导入配置恢复。配置和历史 Excel 只在当前设备中解析，应用没有账号或远端数据写入。

详细规则、数据边界、实现说明和验收标准统一以 [spec.md](./spec.md) 为准，README 不重复维护第二套说明。

## 本地开发

安装依赖并启动开发服务：

```powershell
npm.cmd ci
python dev.py
```

检查生产构建：

```powershell
python dev.py --preview
```

完整验证：

```powershell
npm.cmd run verify
```
